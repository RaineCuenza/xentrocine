# Asset Structure: Public vs Resources

## ❌ Wrong Approach (What We Had Initially)

```
public/
├── css/
│   └── styles.css          # ❌ Directly served, no compilation
└── js/
    └── app-api.js          # ❌ Directly served, no compilation
```

**In Blade:**
```blade
<link rel="stylesheet" href="{{ asset('css/styles.css') }}"/>
<script src="{{ asset('js/app-api.js') }}"></script>
```

**Problems:**
- ❌ No minification (larger file sizes)
- ❌ No cache-busting (browser caches old versions)
- ❌ No hot module reloading (must refresh browser)
- ❌ No build optimization
- ❌ Not following Laravel conventions

---

## ✅ Correct Approach (Current Setup)

```
resources/
├── css/
│   └── styles.css          # ✅ Source file (compiled by Vite)
└── js/
    └── app-api.js          # ✅ Source file (compiled by Vite)

public/
└── build/                   # Auto-generated by Vite
    ├── manifest.json
    └── assets/
        ├── styles-Ckq5paL8.css    # ✅ Compiled with hash
        └── app-api-Dq7IBxtM.js    # ✅ Compiled with hash
```

**In Blade:**
```blade
@vite(['resources/css/styles.css', 'resources/js/app-api.js'])
```

**Benefits:**
- ✅ **Automatic minification** - 40-60% smaller files
- ✅ **Cache-busting** - Hash in filename forces fresh downloads
- ✅ **Hot Module Reloading** - Instant updates in development
- ✅ **Source maps** - Easy debugging in development
- ✅ **Module bundling** - Efficient dependency management
- ✅ **Laravel standard** - Follows framework conventions

---

## How Vite Works

### Development Mode (`npm run dev`)

1. Vite starts dev server on `http://localhost:5173`
2. `@vite()` directive loads files from Vite dev server
3. Files are served with HMR (Hot Module Replacement)
4. Changes to CSS/JS update instantly without page refresh

```
Browser requests: http://localhost:8000/
  ↓
Laravel serves page with: @vite(['resources/css/styles.css'])
  ↓
Vite dev server serves: http://localhost:5173/resources/css/styles.css
  ↓
Browser auto-updates when you save changes to styles.css
```

### Production Mode (`npm run build`)

1. Vite compiles and minifies all assets
2. Generates files in `public/build/assets/` with unique hashes
3. Creates `public/build/manifest.json` mapping
4. `@vite()` directive reads manifest and uses compiled files

```
npm run build
  ↓
Vite compiles: resources/css/styles.css
  ↓
Output: public/build/assets/styles-Ckq5paL8.css (minified)
  ↓
Manifest: { "resources/css/styles.css": "assets/styles-Ckq5paL8.css" }
  ↓
Laravel reads manifest and injects: <link href="/build/assets/styles-Ckq5paL8.css">
```

## Configuration Files

### `vite.config.js`
```javascript
import { defineConfig } from 'vite';
import laravel from 'laravel-vite-plugin';

export default defineConfig({
    plugins: [
        laravel({
            input: [
                'resources/css/styles.css',    // Source CSS
                'resources/js/app-api.js'      // Source JS
            ],
            refresh: true,  // Auto-refresh on Blade changes
        }),
    ],
});
```

### `package.json`
```json
{
    "scripts": {
        "dev": "vite",           // Development with HMR
        "build": "vite build"    // Production build
    },
    "devDependencies": {
        "vite": "^7.0.7",
        "laravel-vite-plugin": "^2.0.0"
    }
}
```

## When to Use Each Approach

### Use `resources/` + Vite (✅ Recommended)
- ✅ **CSS/JS files** - Your application styles and scripts
- ✅ **Development workflow** - Need hot reload and debugging
- ✅ **Production deployment** - Need optimization and caching
- ✅ **Modern applications** - Following Laravel conventions

### Use `public/` directly (⚠️ Limited cases)
- ⚠️ **Static assets** - Images, fonts, PDFs that don't need compilation
- ⚠️ **Third-party libraries** - Pre-built vendor files (though CDN is better)
- ⚠️ **Favicon, robots.txt** - Root-level files

**Example:**
```
public/
├── images/
│   ├── logo.png            # ✅ Static image
│   └── hero.jpg            # ✅ Static image
├── fonts/
│   └── custom-font.woff2   # ✅ Static font
├── favicon.ico             # ✅ Root file
└── robots.txt              # ✅ Root file
```

## Common Pitfalls

### ❌ Mixing approaches
```blade
<!-- DON'T mix asset() and @vite() -->
@vite(['resources/css/styles.css'])
<script src="{{ asset('js/app-api.js') }}"></script>  <!-- ❌ Wrong -->
```

### ❌ Forgetting to run Vite
```bash
# If you see "Vite manifest not found"
npm run build    # For production
# OR
npm run dev      # For development
```

### ❌ Not running Vite in development
```bash
# You need BOTH terminals running:
# Terminal 1
php artisan serve

# Terminal 2
npm run dev      # Don't forget this!
```

---

**Summary:** Always use `resources/` + Vite for your CSS/JS. Only put truly static files (images, fonts, favicon) directly in `public/`. This gives you optimal performance, better caching, and modern development workflow! 🚀
